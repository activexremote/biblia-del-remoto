# Contributing · Cómo contribuir

Thanks for helping improve **The Remote Bible**. It's a living, public reference: the philosophy behind good remote work. Keep it accurate, sourced, and in one voice. · Gracias por mejorar **La Biblia del Remoto**. Es una referencia viva y pública: la filosofía del buen trabajo remoto. Mantenla exacta, con fuentes y en una sola voz.

> This document is bilingual. English first, luego español más abajo.

---

## English

### Ground rules (non-negotiable)

- **Every data claim carries a source.** No source, no claim — mark it `[SOURCE PENDING]` instead of publishing it as fact.
- **Never invent URLs.** If you're not sure a link exists, describe the source and let a maintainer find it.
- **Money in USD.** Convert other currencies and keep the original in parentheses with a date.
- **Both languages are originals, not translations.** If you change `en/X`, review `es/X` in the same pull request — and the other way around.
- **Product names stay in English:** Remote Professional, Remote Founder, Career Accelerator, Global Builder.

### Style

- Direct **"you"** (**tú** in Spanish). No passive-of-courtesy, no "the employee".
- Short sentences, under 20 words. One idea per section.
- Markdown only: `#`/`##`/`###` for headings, GFM pipe tables. No raw HTML.
- Keep the plain, monochrome look. Don't add images or styling.

### How to propose a change

1. **Small fix** (typo, broken link, one sentence): open the `.md` on GitHub, click the pencil, commit to a **new branch**, and open a **Pull Request**.
2. **Bigger change** (new subsection, reworked table): fork or branch, edit, then open a PR that says **what** you changed and **why**.
3. **Just a suggestion or a question:** open an **Issue**. You don't need to write the change yourself.

### What a good pull request looks like

- One topic per PR — it's far easier to review and merge.
- Both languages updated when the content is shared.
- A source added for any new figure or claim.
- A title that says what changed and a description that says why.

### Definition of ready (before you request review)

- [ ] A source on every data claim (or `[SOURCE PENDING]`).
- [ ] No invented URLs.
- [ ] Money in USD.
- [ ] Both `en/` and `es/` updated.
- [ ] Reads in the bible's voice: direct, short, one idea per section.

### Review

A maintainer reviews for accuracy, sources, tone, and bilingual parity. Expect comments — that's the process, not criticism. In the spirit of the bible itself: assume positive intent, no ego, feedback is a gift.

### Repo layout

- `README.md` — the index.
- `en/`, `es/` — the bible, one file per part.
- `en/A1-handbook-prompt.md`, `es/A1-prompt-handbook.md` — appendix (handbook prompt).
- `CONTRIBUTING.md` — this file.

### License

Pick a license before sharing widely. For documentation, **CC BY 4.0** (credit required) or **CC BY-SA 4.0** (credit + share-alike) are common. Until a `LICENSE` file is added, treat the content as **all rights reserved**. By opening a pull request, you agree your contribution can be published under the repository's chosen license.

## Español

### Reglas de oro (no se negocian)

- **Cada dato lleva su fuente.** Sin fuente no hay dato: márcalo `[FUENTE PENDIENTE]` en lugar de publicarlo como cierto.
- **No inventes URLs.** Si no estás seguro de que un enlace exista, describe la fuente y deja que un mantenedor la localice.
- **El dinero va en USD.** Convierte otras monedas y deja el original entre paréntesis con la fecha.
- **Las dos versiones son originales, no traducciones.** Si cambias `es/X`, revisa `en/X` en el mismo pull request, y al revés.
- **Los nombres de producto no se traducen:** Remote Professional, Remote Founder, Career Accelerator, Global Builder.

### Estilo

- Habla de **tú**. Nunca «usted», nunca impersonal, nunca «el alumno».
- Frases de menos de 20 palabras. Una idea por sección.
- Solo Markdown: `#`/`##`/`###` para títulos, tablas en formato GFM. Sin HTML.
- Mantén el aspecto plano y monocromo. No añadas imágenes ni estilos.

### Cómo proponer un cambio

1. **Arreglo pequeño** (errata, enlace roto, una frase): abre el `.md` en GitHub, pulsa el lápiz, haz commit en una **rama nueva** y abre un **Pull Request**.
2. **Cambio grande** (subsección nueva, tabla rehecha): haz un fork o una rama, edita y abre un PR que diga **qué** cambiaste y **por qué**.
3. **Solo una sugerencia o una duda:** abre un **Issue**. No tienes que escribir tú el cambio.

### Cómo es un buen pull request

- Un tema por PR: se revisa y se fusiona mucho mejor.
- Las dos versiones actualizadas cuando el contenido es común.
- Una fuente añadida por cada cifra o afirmación nueva.
- Un título que diga qué cambió y una descripción que diga por qué.

### Definición de listo (antes de pedir revisión)

- [ ] Una fuente en cada dato (o `[FUENTE PENDIENTE]`).
- [ ] Ninguna URL inventada.
- [ ] El dinero en USD.
- [ ] `en/` y `es/` actualizados.
- [ ] Suena a la voz de la biblia: directo, corto, una idea por sección.

### Revisión

Un mantenedor revisa exactitud, fuentes, tono y paridad bilingüe. Habrá comentarios: es el proceso, no una crítica. En el espíritu de la propia biblia: asume buena intención, sin ego, el feedback es un regalo.

### Estructura del repo

- `README.md` — el índice.
- `en/`, `es/` — la biblia, un archivo por parte.
- `en/A1-handbook-prompt.md`, `es/A1-prompt-handbook.md` — apéndice (prompt del handbook).
- `CONTRIBUTING.md` — este archivo.

### Licencia

Elige una licencia antes de difundirlo. Para documentación son habituales **CC BY 4.0** (con atribución) o **CC BY-SA 4.0** (atribución + compartir igual). Hasta que exista un archivo `LICENSE`, trata el contenido como **todos los derechos reservados**. Al abrir un pull request, aceptas que tu contribución se publique bajo la licencia que elija el repositorio.
